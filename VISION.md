# От одного промпта к готовому бизнесу — видение и план

## 1. Что хотим получить

Один промпт от клиента, например:

> «Открой салон красоты в Казани, сделай сайт, запусти рекламу, веди соцсети и считай, чтобы всё окупалось»

…и система сама:

1. Анализирует нишу и город.
2. Находит нужные инструменты на **GitHub** и **Hugging Face**.
3. Собирает сайт и автоматизации.
4. Подключает **Яндекс Метрику** для статистики.
5. Запускает рекламу через **Яндекс Директ**.
6. Создаёт каналы в соцсетях через **Metricool** (или аналог) и назначает ИИ-ведущих.
7. Находит, куда задеплоить/захостить сайт.
8. Ставит ценник так, чтобы всё окупалось.
9. Показывает клиенту готовый бизнес в личном кабинете.

## 2. Трезвая оценка по частям

| Часть | Реально? | Что нужно | Риск |
|-------|----------|-----------|------|
| Яндекс Директ | Да | OAuth-токен, кабинет, лимит бюджета | Реальные деньги — только с подтверждением |
| Яндекс Метрика | Да | ID счётчика, токен API | Низкий |
| Иностранный сервер + VPN/прокси | Да | VPS, прокси, настройка `HTTPS_PROXY` | Юридический/сетевой — решает владелец |
| ChatGPT / LLM | Да, но | API доступен не из всех регионов (уже получили 403) | Нужен прокси или замена (GigaChat/Yandex/OpenRouter) |
| Скиллы из GitHub | Да, как **поиск и реестр** | GitHub API, topic search | Нельзя слепо выполнять чужой код — только allowlist |
| Hugging Face | Да | HF API Models/Spaces | Модели надо проверять и限额 по ресурсам |
| Metricool / соцсети | Да | Аккаунт, API-ключ, каналы | Контент-модерация, квоты платформ |
| Несколько ИИ-ведущих | Да | LLM + планировщик постов | Нужен человек-контролёр на старте |
| Деплой/хостинг | Да | Curated список провайдеров + API | Стоимость, доступность |
| Ценник и окупаемость | Да | Модель себестоимости и LTV | Ошибки в прогнозе — нужные данные |

**Вывод:** «полная автоматизация по одному промпту» достижима как **оркестрированный конвейер с контрольными точками**, а не как безнадзорный робот, который тратит деньги. На старте каждое действие, связанное с деньгами или публикацией, требует подтверждения клиента.

## 3. Расширенная архитектура

```text
ПРОМПТ КЛИЕНТА
      │
      ▼
BusinessPlanner (LLM / правила)
      │
      ├─► GitHubToolRegistry   — поиск репозиториев/скиллов (только метаданные)
      ├─► HuggingFaceRegistry  — поиск моделей и Spaces
      │
      ▼
ПЛАН (шаги + смета + риски) ──► подтверждение клиента
      │
      ├─► SiteBuilder      → сайт на поддомене
      ├─► MetricaService   → счётчик, цели, дашборд
      ├─► DirectService    → кампании, объявления, бюджет (с лимитом)
      ├─► SocialService    → каналы, контент-план, ИИ-ведущие
      ├─► DeployService    → выбор хостинга, публикация
      └─► PricingEngine    → цена, маржа, окупаемость
      │
      ▼
дашборд в личном кабинете + мониторинг + отчёты
```

## 4. Что нужно от вас (данные и доступы)

| Сервис | Что выдать |
|--------|------------|
| OpenAI / замена | ключ + доступный `OPENAI_BASE_URL` или прокси |
| VPS / VPN | адрес, порт, логин, ключ |
| Яндекс Директ | OAuth-токен, ID клиента, лимит бюджета |
| Яндекс Метрика | ID счётчика, токен API |
| Metricool (или аналог) | аккаунт, API-ключ, список соцсетей |
| Хостинг | аккаунт/токен на выбранном провайдере |

## 5. Ветви под направления

Создаются от `feature/novofon` (там уже есть кабинет и колл-центр):

- `feature/yandex-ads` — Директ + Метрика.
- `feature/metricool` — соцсети и ИИ-ведущие.
- `feature/agent-hub` — GitHub/HF registry, планировщик, один промпт.
- `feature/pricing` — ценник, маржа, окупаемость.

## 6. Правила безопасности

1. Никакого слепого выполнения кода из найденных репозиториев — только проверенный allowlist.
2. Любая трата денег (реклама, хостинг) — только после явного подтверждения и с лимитом.
3. Публикация в соцсети — с очередью на модерацию.
4. Секреты только в `.env`, не в git и не в чат.
5. Все внешние вызовы логируются; есть кнопка «стоп».

## 7. Что уже реализовано (25 ноября, ветка `feature/agent-hub`)
