# Novofon — нужен или нет?

## Короткий ответ

**Для демо — не нужен.** Сейчас работают `MockProvider` и разговор в браузере.

**Для реальных звонков по России — скорее да.** Twilio — международный оператор: звонить на российские номера можно не всегда, дороже, а caller ID часто определяется плохо. Novofon даёт российские номера и дешёвые исходящие звонки по РФ/СНГ.

Поэтому в репозитории создана отдельная ветка `feature/novofon` и заготовка `NovofonProvider`.

## В чём разница

| | Twilio | Novofon |
|---|---|---|
| Регион | Международный | Россия / СНГ |
| Номер | Часто внешний, с ограничениями | Российский городской/мобильный DID |
| Интерфейс | REST API + WebSocket-аудио «из коробки» | В основном SIP; нужен медиа-шлюз |
| Стоимость звонков по РФ | Выше | Ниже |
| готовность интеграции | Уже реализована | Нужны SIP-доступ и шлюз |

## Как будет выглядеть интеграция

```text
Личный кабинет
     │ POST /api/calls
     ▼
CallManager → NovofonProvider
     │ SIP-команда на originate
     ▼
SIP-шлюз (Asterisk / FreeSWITCH)  ← контейнер рядом с приложением
     │ SIP/RTP
     ▼
Novofon → телефон клиента

Аудио звонка:
телефон → Novofon → шлюз → WebSocket /ws/twilio → STT → ИИ → TTS → WebSocket → шлюз → трубка
```

 Twilio отдаёт звук сразу по WebSocket. Novofon — SIP-оператор, поэтому между ним и нашим ИИ нужен **медиа-шлюз**: он принимает RTP-поток, переводит его в 8 кГц mu-law/PCM и отдаёт нам по WebSocket. Логика ИИ при этом не меняется — переиспользуем `/ws/twilio` или сделаем `/ws/novofon` с тем же протоколом.

## Что нужно от вас

1. SIP-аккаунт Novofon: **логин, пароль, SIP-сервер**.
2. Номер (DID), с которого звоним, и разрешение на исходящие — в том числе на мобильные.
3. Уточнить, есть ли в тарифе **HTTP API для originate**. Если да — обойдёмся без части SIP-команд вручную.
4. Публичный адрес/порты для SIP-шлюза, если шлюз будет в нашем контейнере.

Переменные в `.env`:

```text
CALL_PROVIDER=novofon
NOVOFON_SIP_HOST=
NOVOFON_SIP_USER=
NOVOFON_SIP_PASSWORD=
NOVOFON_FROM_NUMBER=
NOVOFON_GATEWAY_WS_URL=
```

## Что уже сделано

- Ветка `feature/novofon` создана от `feature/call-center` и запушена.
- `NovofonProvider` добавлен в реестр провайдеров; без настроек он честно пишет ошибку с подсказкой.
- Переменные окружения добавлены в `config.py` и `.env.example`.

## Что будет после получения данных

1. Поднять Asterisk/FreeSWITCH в Docker, зарегистрировать SIP-аккаунт Novofon.
2. Настроить исходящий контекст и media-мост в наш WebSocket.
3. Дописать `NovofonProvider.start_call()` (через API или SIP originate).
4. Протестировать реальный звонок на ваш номер.
5. Слить `feature/novofon` в `feature/call-center`, а затем в `main`.

Точный набор SIP-параметров и наличие HTTP API зависят от вашего тарифа — уточните их в личном кабинете Novofon или в поддержке.
